# 證據卡：好的上下文長什麼樣子
wiki: concepts/designing-good-context.md

- **GOOD-1** Anthropic 的核心原則：找出最小的一組高訊號 token，讓想要的結果最可能發生。 [S5]
- **GOOD-2** 系統提示要寫在「剛好的高度」：不要寫成死板的 if-else 規則，也不要寫成假設對方都懂的空泛指示。 [S5]
- **GOOD-3** 精簡不代表短。先用最少的提示測試，再根據實際出錯的地方補上指令與範例。 [S5]
- **GOOD-4** 工具：避免太多、選擇模糊不清。如果人類工程師都說不出某個情況該用哪個工具，agent 也做不到。 [S5]
- **GOOD-5** 範例：不要塞一長串特殊情況，而是挑少量、多樣、有代表性的例子。 [S5]
- **GOOD-6** Anthropic 建議提供少量、多樣、有代表性的範例；Manus 提醒 agent 會模仿上下文裡累積的「動作與結果」紀錄，紀錄太一致時會陷入固定做法，要加入少量變化。兩者談的對象不同，方向一致。 [S5][S6]
