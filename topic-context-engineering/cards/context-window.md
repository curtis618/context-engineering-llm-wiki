# 證據卡：上下文視窗
wiki: concepts/context-window.md

- **WIN-1** Karpathy 的比喻：LLM 像一種新的作業系統，模型是 CPU，上下文視窗是 RAM，也就是模型的工作記憶。 [S2]
- **WIN-2** 視窗裡裝三類東西：指令（提示詞、範例、工具說明）、知識（事實與記憶）、工具回傳的結果。 [S2]
- **WIN-3** 任務一長，工具回傳的內容不斷累積，後果有三種：超出上下文視窗、成本與延遲暴增、表現變差。 [S2]
- **WIN-4** 上下文必須被當成有限資源，而且邊際效益遞減：放越多，每一份新增內容的幫助越小。 [S5]
- **WIN-5** 模型有「注意力預算」，每多一個 token 就會消耗一點。 [S5]
- **WIN-6** 原因在模型架構：每個 token 都要和其他所有 token 建立關係，n 個 token 就有 n² 組關係。 [S5]
- **WIN-7** 表現是逐漸變差，不是到某個長度突然崩潰。 [S5]
- **WIN-8** 等視窗變大不能解決問題，因為內容被污染、不相關的問題依然存在。 [S5]
