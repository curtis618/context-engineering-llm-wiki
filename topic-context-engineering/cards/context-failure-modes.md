# 證據卡：上下文的四種失敗模式
wiki: concepts/context-failure-modes.md

- **FAIL-1** 上下文視窗已經大到 1M token，但更長的上下文不會產生更好的回答。 [S3]
- **FAIL-2** 污染：幻覺或其他錯誤跑進上下文，之後被反覆引用。 [S2][S3]
- **FAIL-3** 污染的例子（據該文轉述）：玩寶可夢的 Gemini agent，「目標」被錯誤的遊戲狀態污染後，做出沒有意義的策略並重複同樣行為。 [S3]
- **FAIL-4** 分心：上下文太長，模型過度專注在上下文，忽略了訓練時學到的東西。 [S2][S3]
- **FAIL-5** 分心的研究（據該文轉述）：Databricks 發現 Llama 3.1 405b 的正確率在約 32k token 時開始下降。 [S3]
- **FAIL-6** 混淆：上下文裡多餘的內容被模型拿去用，產生品質差的回答。 [S2][S3]
- **FAIL-7** 混淆的例子（據該文轉述）：給量化版 Llama 3.1 8b 全部 46 個工具時會失敗；只給 19 個工具就成功。 [S3]
- **FAIL-8** 衝突：新加入的資訊或工具，和上下文裡原有的資訊互相矛盾。 [S2][S3]
- **FAIL-9** 衝突的研究（據該文轉述）：把測驗題拆成多輪對話分次給模型，表現平均下降 39%；OpenAI 的 o3 從 98.1 降到 64.1。 [S3]
- **FAIL-10** 原因：前面幾輪的錯誤嘗試留在上下文裡，模型一旦走錯方向就迷路，回不來。 [S3]
- **FAIL-11** 以下的研究與例子都是〈How Long Contexts Fail〉一文的轉述，本 wiki 沒有讀原始研究。 [S3]
