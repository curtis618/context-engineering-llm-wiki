# 上下文的四種失敗模式

> 一句話：上下文不是越多越好，塞錯東西會讓模型以四種方式出錯。

## 前提：視窗變大不等於回答變好

- 上下文視窗已經大到 1M token，但更長的上下文不會產生更好的回答。 [S3]
- Agent 最容易受害，因為它靠上下文來收集資訊、整合發現、協調行動。 [S3]
- 這四種分類由 Drew Breunig 提出，LangChain 的文章也引用了它。 [S2]

## 污染（Context Poisoning）

- 定義：幻覺（模型編出來的錯誤內容）或其他錯誤跑進上下文，之後被反覆引用。 [S2][S3]
- 例子：玩寶可夢的 Gemini agent，上下文裡的「目標」被錯誤的遊戲狀態污染後，做出沒有意義的策略並重複同樣行為，而且要很久才能修正。 [S3]

## 分心（Context Distraction）

- 定義：上下文太長，模型過度專注在上下文，忽略了訓練時學到的東西。 [S2][S3]
- 例子：同一個寶可夢 agent 在上下文遠超過 100k token 後，傾向重複過去做過的動作，而不是想出新計畫。 [S3]
- 研究：Databricks 發現 Llama 3.1 405b 的正確率在約 32k token 時開始下降，較小的模型更早。 [S3]

## 混淆（Context Confusion）

- 定義：上下文裡多餘的內容被模型拿去用，產生品質差的回答。 [S2][S3]
- 研究：在 Berkeley 的工具呼叫排行榜上，每個模型在拿到超過一個工具時表現都變差，還會呼叫不相關的工具。 [S3]
- 例子：給量化版 Llama 3.1 8b 全部 46 個工具時會失敗，即使內容遠低於 16k 的視窗上限；只給 19 個工具就成功。 [S3]

## 衝突（Context Clash）

- 定義：新加入的資訊或工具，和上下文裡原有的資訊互相矛盾。 [S2][S3]
- 研究：Microsoft 與 Salesforce 把測驗題拆成多輪對話分次給模型，表現平均下降 39%；OpenAI 的 o3 從 98.1 降到 64.1。 [S3]
- 原因：前面幾輪的錯誤嘗試留在上下文裡，模型一旦走錯方向就迷路，回不來。 [S3]
