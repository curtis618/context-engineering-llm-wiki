# Context Rot（上下文腐化）

> 一句話：輸入越長，模型的表現越不可靠，即使任務本身很簡單。

## 現象

- 一般假設模型會平均地使用整段上下文；Chroma 的實驗顯示不是，輸入越長，表現越不可靠。 [S4]
- Chroma 測試了 18 個模型，包含 GPT-4.1、Claude 4、Gemini 2.5 與 Qwen3 系列。 [S4]
- 實驗刻意讓任務保持簡單，只改變輸入長度，所以量到的是「長度本身」的影響。 [S4]
- 作者認為真實應用比實驗複雜，長度的影響在實務上只會更明顯。 [S4]

## 實驗發現

- 干擾句（和問題相關但不是答案的句子）：只加一個，表現就比沒有干擾時差；加到四個更差。 [S4]
- 語意相似度：問題和答案句越不像，表現隨長度下降得越快；輸入短的時候則沒有這個問題。 [S4]
- 文章結構：順序正常、前後連貫的長文，反而比句子被隨機打亂的長文更難找到答案，18 個模型都是如此。 [S4]
- 對話記憶測驗：只給相關片段（約 300 token）時的表現，明顯高於給完整歷史（約 113k token）時。 [S4]

## Anthropic 的說法與解釋

- Anthropic 對 context rot 的描述：視窗裡的 token 越多，模型準確回想其中資訊的能力就越低；所有模型都有這個現象，只是程度不同。 [S5]
- 原因之一：n 個 token 之間有 n² 組關係要顧，內容越長，注意力越分散。 [S5]
- 原因之二：訓練資料裡短的文字比長的多，模型處理長距離關係的經驗比較少。 [S5]
